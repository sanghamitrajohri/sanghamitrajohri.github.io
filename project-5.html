RecoverIQ: Cost-Aware Recovery for AI Coding Agents

Personal project, demoed live at AI Tinkerers (Oct 2026) — code · project page

Python · LangGraph · Claude API · TypeSafe Jev · Streamlit · macOS sandbox-exec

Problem

When a coding agent fails, the usual fix is to retry. But failures have different causes: a provider blip, a model that ran out of output tokens, a workspace that was silently damaged, a requirement nobody wrote down, or a task that can't be done. Each one has a different cheap fix, and retrying blindly pays for the same failure again and again.

Research question: does Jev-guided recovery deliver more verified task completions per dollar than fixed retry or hand-written recovery rules?

Architecture

What I Built

  • A real coding agent that reads a buggy file and its visible tests, asks Claude for a fix, validates the reply, and runs pytest under macOS sandbox-exec (no network, no home-directory reads, writes only to the workspace).
  • A LangGraph controller with five recovery actions that really do something: a new LLM call on retry, a bigger model on switch, hash-verified checkpoint restore, a human-in-the-loop pause, and terminate.
  • Jev integration through TypeSafe's SDK, plus a deterministic policy layer that rejects unaffordable, unsafe or invalid actions. Jev proposes; the policy disposes.
  • A benchmark harness of 10 reproducible failure scenarios with hidden acceptance tests, a per-event cost ledger, and a Streamlit dashboard that races strategies side by side.
  • An integrity audit that flags "successes" where the model gamed the tests or left helper files damaged, so only clean fixes count.

Evaluation

Live run, 2026-10-19: 108 runs with real Claude and real Jev, $2.41 total. 3 repeats × 9 tasks × 4 strategies.

StrategyClean fixesAPI costClean fixes per $
Fixed retry12 / 27$0.3831.3
Rule-based21 / 27$0.8325.3
Jev only24 / 27$0.6437.3
RecoverIQ (Jev + retry gate)24 / 27$0.5642.9

Results

RecoverIQ spent 33% less than the rule-based baseline for more clean fixes, with zero budget violations. The biggest gap was silent workspace corruption: Jev restored the checkpoint 3 of 3 times for $0.007 in total, while the rules failed all 3 for $0.36.

A checkout task made it easy to see. A store's tax setting is changed from 8% to 80% while the agent fixes a shipping bug. RecoverIQ fixed it cleanly every time in about 10 seconds for $0.0068. Fixed retry gave up. The rule-based strategy escalated to the expensive model, which "passed" by rewriting the settings file.

Caveats: 3 repeats per cell is a small sample, and the retry gate was tuned after the first live call. If human time is priced at $0.50 per escalation, fixed retry has the best ratio because it never asks a human.

Lessons

"Tests pass" is not the same as "fixed". Real models will game contradictory tests (Opus returned a str subclass whose __eq__ made both tests pass) or patch around damage instead of repairing it. Measuring clean successes, and labeling every simulated number as simulated, mattered more than any single strategy choice.
