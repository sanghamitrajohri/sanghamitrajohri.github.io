KV-Caching for Transformer Inference

Independent research, University of Washington — built on the open-source nanoGPT codebase

CUDA · PyTorch · NVIDIA Nsight Systems

Problem

nanoGPT's naive autoregressive decoding recomputes attention over the full sequence at every generation step — redoing work it already did on the previous token. On longer sequences that wasted compute dominates generation latency.

Architecture

What I Built

  • Implemented KV-caching in nanoGPT so each decoding step reuses previously computed key/value tensors instead of recomputing them.
  • Benchmarked transformer components — Flash-Attention, MLPs, GEMM operations — across batch sizes (1–64) and sequence lengths (256–16,384) to see where time was actually spent.

Optimization

  • Used NVIDIA Nsight Systems and the PyTorch Profiler to separate memory-bandwidth-bound stages from compute-bound ones.
  • Swept batch size and sequence length together, since their interaction — not either alone — determined arithmetic intensity.

Evaluation

MetricBeforeAfterΔ
Per-token generation speedbaselineKV-cached2.0× faster
Batch inference (batch sizes 1–64)baselineoptimized3× speedup

Results

KV-caching alone delivered a 2× improvement in per-token generation speed. Sweeping batch size and sequence length surfaced a further 3× speedup opportunity for batched inference — the kind of finding that only shows up when you profile across the full parameter space instead of one configuration.

Lessons

The naive implementation isn't slow because the GPU is slow — it's slow because it's asked to redo work. KV-caching is a small code change with an outsized effect, exactly the kind of thing profiling is good at surfacing and intuition alone tends to miss.
